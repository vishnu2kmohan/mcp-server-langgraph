# 93. OpenFGA Relation Inheritance Patterns

Date: 2026-01-04

## Status

Accepted

## Category

Security / Authorization

## Context

During a comprehensive OpenFGA authorization audit, we discovered a subtle but critical bug pattern in our relation inheritance model. The bug manifested when:

1. A WebSocket endpoint required a specific relation (e.g., `user`)
2. A user had a "higher privilege" relation (e.g., `admin`)
3. The model did NOT compute the required relation from the higher privilege relation
4. The user was DENIED access despite appearing to have sufficient privileges

### The ai:suggestions Bug

The specific bug that triggered this ADR:

- **Endpoint**: `/api/v1/ws/ai/suggestions`
- **Required Relation**: `user` on `ai:suggestions`
- **Admin's Tuple**: `(user:admin, admin, ai:suggestions)`
- **Expected**: Admin should have access (admin is "higher" than user)
- **Actual**: Admin DENIED access

The root cause was the `ai` type model definition:

```json
// BEFORE FIX (caused the bug)
{
  "type": "ai",
  "relations": {
    "user": { "this": {} },           // Direct assignment only - THE BUG
    "admin": { "this": {} },          // Direct assignment only
    "viewer": {                        // Computed from user OR admin
      "union": { "child": [
        { "this": {} },
        { "computedUserset": { "relation": "user" } },
        { "computedUserset": { "relation": "admin" } }
      ]}
    }
  }
}
```

**Problem**: `viewer` is computed from `admin`, but `user` is NOT computed from `admin`.

## Decision

We refactored the OpenFGA model to **properly compute lower-privilege relations from higher-privilege relations**, eliminating the need for redundant explicit tuples.

### 1. Model Refactoring (Primary Solution)

The model was updated to compute `user` from `admin` for types that had this gap:

**Fixed ai type:**
```json
{
  "type": "ai",
  "description": "AI features (ADR-0093: admin → user inheritance)",
  "relations": {
    "user": {
      "union": { "child": [
        { "this": {} },
        { "computedUserset": { "relation": "admin" } }
      ]}
    },
    "admin": { "this": {} },
    "viewer": {
      "union": { "child": [
        { "this": {} },
        { "computedUserset": { "relation": "user" } },
        { "computedUserset": { "relation": "admin" } }
      ]}
    }
  }
}
```

**Fixed system type:**
```json
{
  "type": "system",
  "description": "System-level access (ADR-0093: admin → developer, user, viewer)",
  "relations": {
    "admin": { "this": {} },
    "developer": {
      "union": { "child": [
        { "this": {} },
        { "computedUserset": { "relation": "admin" } }
      ]}
    },
    "user": {
      "union": { "child": [
        { "this": {} },
        { "computedUserset": { "relation": "admin" } }
      ]}
    },
    "viewer": {
      "union": { "child": [
        { "this": {} },
        { "computedUserset": { "relation": "admin" } }
      ]}
    }
  }
}
```

**Fixed conversation type:**
```json
{
  "type": "conversation",
  "relations": {
    "owner": { "this": {} },
    "editor": {
      "union": { "child": [
        { "this": {} },
        { "computedUserset": { "relation": "owner" } }
      ]}
    },
    "viewer": {
      "union": { "child": [
        { "this": {} },
        { "computedUserset": { "relation": "editor" } }
      ]}
    }
  }
}
```

### 2. Contract Test for Relation Coverage

A new contract test validates that all WebSocket endpoints are accessible to intended users:

**Location**: `tests/contract/test_websocket_authorization_relation_coverage.py`

**Key Tests**:
- `test_admin_can_access_all_non_excluded_endpoints`: Verifies admin is never denied access
- `test_ai_suggestions_accessible_to_all_users`: Specific regression test for the bug
- `test_all_websocket_authz_configs_are_satisfiable`: Ensures at least one user can access each endpoint

### 3. Model Inheritance Analyzer

A validation script analyzes the OpenFGA model for potential inheritance gaps:

**Location**: `scripts/validation/analyze_openfga_inheritance.py`

**Usage**:
```bash
# Human-readable report
python scripts/validation/analyze_openfga_inheritance.py -v

# JSON output for CI
python scripts/validation/analyze_openfga_inheritance.py --json

# Fail if high-severity gaps found
python scripts/validation/analyze_openfga_inheritance.py --fail-on-high
```

**Output Example**:
```
HIGH SEVERITY GAPS (Require explicit tuples)
--------------------------------------------------------------------------------
Type: ai
  Gap: admin → user
  Issue: 'user' is NOT computed from 'admin'. Users with 'admin'
         relation will be DENIED access to endpoints requiring 'user' relation.
  Fix: Add explicit 'user' tuples for users who have 'admin' relation.
```

### 4. Documentation of Intentional Exclusions

The `sample-tuples.json` metadata now includes an `intentional_exclusions` section documenting which access restrictions are by design:

```json
{
  "metadata": {
    "intentional_exclusions": {
      "authz:playground": "bob excluded - only admin/developer should access",
      "identity:keycloak": "alice/bob excluded - admin-only for security",
      "workflow:hitl": "bob excluded - only editors can approve HITL requests"
    }
  }
}
```

## Relation Hierarchy Reference

### Standard Privilege Hierarchy

Most types follow this inheritance pattern (higher → lower):

```
owner → admin → editor → viewer
          ↘        ↘
           user    user
```

### Types with Proper Inheritance (After ADR-0093 Refactoring)

These types now properly compute lower-privilege relations from higher-privilege relations:

| Type | Pattern | Status |
|------|---------|--------|
| `ai` | `admin` → `user` → `viewer` | **Fixed** - admin implicitly has user access |
| `system` | `admin` → `developer`, `admin` → `user`, `admin` → `viewer` | **Fixed** - admin implicitly has all sub-persona access |
| `conversation` | `owner` → `editor` → `viewer` | **Fixed** - proper hierarchy |
| `mcp` | `user` → `viewer` | No `admin` relation (by design) |

## Implementation Checklist

When adding a new WebSocket endpoint with authorization:

1. **Define the required relation** in `WebSocketConfig.authz_required_relation`
2. **Check the model** - Does the required relation inherit from higher privileges?
3. **Add tuples** for all intended users in `sample-tuples.json`
4. **Run the contract test** to verify access:
   ```bash
   pytest tests/contract/test_websocket_authorization_relation_coverage.py -v
   ```
5. **Run the analyzer** to check for new gaps:
   ```bash
   python scripts/validation/analyze_openfga_inheritance.py --fail-on-high
   ```

## Consequences

### Positive

- **Proper Inheritance**: Model now correctly computes lower-privilege relations from higher-privilege ones
- **No Redundant Tuples**: Admins no longer need explicit `user` tuples - inheritance is automatic
- **Regression Prevention**: Contract tests catch inheritance gaps before deployment
- **Visibility**: Analyzer script makes inheritance patterns visible during audits
- **TDD Validated**: 30+ unit tests validate the expected inheritance behavior

### Negative

- **Model Complexity**: Relation definitions are slightly more complex with union/computedUserset
- **Maintenance**: Must ensure new types follow the standard inheritance pattern
- **Migration**: Existing deployments may need OpenFGA model updates

### Risks and Mitigations

| Risk | Mitigation |
|------|------------|
| Model changes breaking access | 38 tests validate inheritance patterns |
| New types with inheritance gaps | Analyzer detects gaps on every run |
| Intentional exclusions being bypassed | Documented in metadata with rationale |
