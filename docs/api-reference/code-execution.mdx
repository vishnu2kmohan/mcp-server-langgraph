## Overview

The Code Execution API provides endpoints for running Python code in isolated sandbox environments. All operations are authenticated and authorized via JWT tokens.

<Warning>
Code execution is **disabled by default**. Enable via `ENABLE_CODE_EXECUTION=true` before using these endpoints.
</Warning>

---

## Run Code

Execute code or operations in a sandboxed environment.

<ParamField path="POST" method="/api/v1/sandbox/run">
  Execute a sandboxed operation
</ParamField>

### Request Body

<ParamField body="type" type="string" required>
  Operation type: `python`, `bash`, `web_fetch`, `write_file`, `edit_file`, `screenshot`, `computer_use`
</ParamField>

<ParamField body="code" type="string">
  Python code to execute (for type: `python`)
</ParamField>

<ParamField body="command" type="string">
  Shell command to execute (for type: `bash`)
</ParamField>

<ParamField body="url" type="string">
  URL to fetch (for type: `web_fetch`)
</ParamField>

<ParamField body="file_path" type="string">
  File path for write/edit operations
</ParamField>

<ParamField body="content" type="string">
  File content (for type: `write_file`)
</ParamField>

<ParamField body="old_string" type="string">
  String to find (for type: `edit_file`)
</ParamField>

<ParamField body="new_string" type="string">
  Replacement string (for type: `edit_file`)
</ParamField>

<ParamField body="replace_all" type="boolean" default="false">
  Replace all occurrences (for type: `edit_file`)
</ParamField>

<ParamField body="payload" type="object">
  Additional payload for `screenshot` and `computer_use` operations
</ParamField>

<ParamField body="timeout" type="integer">
  Override default timeout in seconds (max: 600)
</ParamField>

### Response

<ResponseField name="stdout" type="string">
  Standard output from execution
</ResponseField>

<ResponseField name="stderr" type="string">
  Standard error from execution
</ResponseField>

<ResponseField name="exit_code" type="integer">
  Process exit code (0 = success)
</ResponseField>

<ResponseField name="duration_ms" type="float">
  Execution duration in milliseconds
</ResponseField>

<ResponseField name="timed_out" type="boolean">
  Whether execution was killed due to timeout
</ResponseField>

<ResponseField name="error" type="string">
  Error message if execution failed
</ResponseField>

## Examples

### Execute Python Code

<CodeGroup>

```bash Request
curl -X POST http://localhost:8000/api/v1/sandbox/run \
  -H "Authorization: Bearer $JWT" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "python",
    "code": "import json\ndata = {\"result\": sum(range(10))}\nprint(json.dumps(data))"
  }'
```

```json Response
{
  "stdout": "{\"result\": 45}\n",
  "stderr": "",
  "exit_code": 0,
  "duration_ms": 156.3,
  "timed_out": false
}
```

</CodeGroup>

## Error Responses

### 400 Bad Request

```json
{
  "detail": "Invalid operation type: unknown"
}
```

### 403 Forbidden

```json
{
  "detail": "Code execution is disabled. Set ENABLE_CODE_EXECUTION=true"
}
```

### 408 Request Timeout

```json
{
  "stdout": "",
  "stderr": "",
  "exit_code": 124,
  "duration_ms": 30000,
  "timed_out": true,
  "error": "Execution exceeded timeout of 30 seconds"
}
```

### 500 Internal Server Error

```json
{
  "detail": "Sandbox execution failed: Docker daemon not available"
}
```

## Resource Limits

All executions are subject to resource limits:

| Resource | Default | Environment Variable |
|----------|---------|---------------------|
| Timeout | 30s | `CODE_EXECUTION_TIMEOUT` |
| Memory | 512MB | `CODE_EXECUTION_MEMORY_LIMIT_MB` |
| CPU | 1.0 cores | `CODE_EXECUTION_CPU_QUOTA` |
| Disk | 100MB | `CODE_EXECUTION_DISK_QUOTA_MB` |
| Processes | 1 | `CODE_EXECUTION_MAX_PROCESSES` |
| Network | none | `CODE_EXECUTION_NETWORK_MODE` |
