### Overview

Proper environment configuration is critical for maintaining consistency across development, stg, and production environments while keeping sensitive data secure. This guide covers configuration strategies, environment management, and the 12-factor app methodology.

<Info>
Environment-based configuration enables seamless deployment across multiple environments while maintaining security and flexibility.
</Info>

### Configuration Strategies

#### 12-Factor App Principles

The MCP Server follows the [12-Factor App](https://12factor.net/) methodology for configuration:

<CardGroup cols={2}>
  <Card title="Environment Variables" icon="terminal">
    - Store config in environment
    - Never commit secrets to git
    - Strict separation of config and code
    - Different values per environment
  </Card>

  <Card title="Backing Services" icon="database">
    - Attached resources via URLs
    - Swap services without code changes
    - Database URLs, cache URLs, etc.
    - Service discovery via environment
  </Card>

  <Card title="Build, Release, Run" icon="rocket">
    - Separate build and run stages
    - Config injected at runtime
    - Immutable releases
    - Rollback capability
  </Card>

  <Card title="Port Binding" icon="plug">
    - Export services via port binding
    - Completely self-contained
    - No runtime injection of webserver
    - Configurable port via environment
  </Card>
</CardGroup>

### Environment Variable Management

#### Required Variables

<ParamField path="ENV" type="string" required>
  Environment name: `development`, `stg`, or `production`
</ParamField>

<ParamField path="AUTH_PROVIDER" type="string" required>

</ParamField>

<ParamField path="WORKERS" type="integer" default="4">

#### Alert Notification Variables

**Web Push (VAPID)**:

Web Push notifications require VAPID (Voluntary Application Server Identification) keys for secure browser push notifications. Generate keys using:

```bash
npx web-push generate-vapid-keys
```

```properties
## Web Push VAPID Configuration
VAPID_PUBLIC_KEY=BLc4xRLA...your-public-key
VAPID_PRIVATE_KEY=your-private-key
VAPID_CLAIMS_EMAIL=admin@yourdomain.com
```

<Warning>
VAPID keys are required for push notifications. Without them, the push notification system will be disabled and alerts will only be delivered via WebSocket.
</Warning>

**Database URL for Production Stores**:

In production/stg environments, push subscriptions and AI feedback are stored in PostgreSQL. Configure the database URL:

```properties
## Database for persistent stores (production/stg)
DATABASE_URL=postgresql+asyncpg://user:password@localhost:5432/mcp_server

## Compliance storage backend
COMPLIANCE_STORAGE_BACKEND=postgres
COMPLIANCE_POSTGRES_URL=postgresql+asyncpg://user:password@localhost:5432/mcp_server
```

<Info>
**Environment-Aware Store Selection**: The application automatically selects the appropriate storage backend based on environment:
- **Development/Test**: In-memory stores (no persistence)
- **Production/STG**: PostgreSQL stores (requires `DATABASE_URL`)

This enables fast local development while ensuring data durability in production.
</Info>

```dockerfile

CMD ["sh", "-c", "uvicorn src.main:app --host 0.0.0.0 --port $PORT --workers $WORKERS"]
```

### Configuration Validation

#### Pydantic Settings

Use Pydantic for type-safe configuration:

```python
from pydantic_settings import BaseSettings, SettingsConfigDict
from typing import Literal, Optional

class Settings(BaseSettings):
    """Application settings with validation"""

    model_config = SettingsConfigDict(
        env_file=".env",
        env_file_encoding="utf-8",
        case_sensitive=False,
        extra="ignore"
    )

    # Environment
    env: Literal["development", "stg", "production"] = "development"
    debug: bool = False
    log_level: Literal["debug", "info", "warning", "error"] = "info"

    # Server
    host: str = "0.0.0.0"
    port: int = 8000
    workers: int = 4

    # Authentication
    auth_provider: Literal["inmemory", "keycloak"] = "inmemory"
    jwt_secret: str
    jwt_algorithm: str = "HS256"
    jwt_expiration: int = 3600

    # Session
    session_provider: Literal["memory", "redis"] = "memory"
    session_secret: str
    session_ttl: int = 3600

    # LLM
    llm_provider: Literal["anthropic", "openai", "google", "ollama"]
    anthropic_api_key: Optional[str] = None
    openai_api_key: Optional[str] = None
    google_api_key: Optional[str] = None

    # Validation
    def __init__(self, **kwargs):
        super().__init__(**kwargs)
        self._validate_config()

    def _validate_config(self):
        """Validate configuration consistency"""

        # Production checks
        if self.env == "production":
            assert not self.debug, "DEBUG must be false in production"
            assert self.auth_provider == "keycloak", "Use Keycloak in production"
            assert self.session_provider == "redis", "Use Redis sessions in production"

        # LLM API key required
        if self.llm_provider == "anthropic":
            assert self.anthropic_api_key, "ANTHROPIC_API_KEY required"
        elif self.llm_provider == "openai":
            assert self.openai_api_key, "OPENAI_API_KEY required"
        elif self.llm_provider == "google":
            assert self.google_api_key, "GOOGLE_API_KEY required"

## Load and validate settings
settings = Settings()
```

#### Startup Validation

Validate configuration on application startup:

```python
from fastapi import FastAPI
from src.config import settings
import sys

app = FastAPI()

@app.on_event("startup")
async def validate_startup_config():
    """Validate configuration before accepting requests"""

    errors = []

    # Check required services
    if settings.auth_provider == "keycloak":
        try:
            # Test Keycloak connection
            response = await httpx.get(f"{settings.keycloak_url}/health")
            if response.status_code != 200:
                errors.append("Keycloak is not healthy")
        except Exception as e:
            errors.append(f"Cannot connect to Keycloak: {e}")

    if settings.session_provider == "redis":
        try:
            # Test Redis connection
            redis_client = await aioredis.from_url(settings.redis_url)
            await redis_client.ping()
        except Exception as e:
            errors.append(f"Cannot connect to Redis: {e}")

    # Check LLM API key
    if settings.llm_provider == "anthropic" and not settings.anthropic_api_key:
        errors.append("ANTHROPIC_API_KEY is required")

    # Fail fast if errors
    if errors:
        for error in errors:
            print(f"❌ Configuration Error: {error}", file=sys.stderr)
        sys.exit(1)

    print("✅ Configuration validated successfully")
```
### Environment-Specific Features

#### Feature Flags

Enable features based on environment:

<ParamField path="FF_TEST_MODE" type="boolean" default="false">
  **Testing Feature Flag Bypass**

  When set to `true`, all feature flag checks via `require_feature()` and `@feature_gated` decorator are bypassed. This enables testing of feature-gated functionality without needing to enable each feature flag individually.

  **Use Cases:**
  - Integration tests that need all features available
  - Development environments for rapid prototyping
  - CI/CD pipelines testing disabled features

  **Security Note:** Never enable in production. This flag is automatically set in the test environment via `conftest.py`.
</ParamField>

##### Using the `@feature_gated` Decorator

The `@feature_gated` decorator provides a cleaner alternative to calling `require_feature()` manually:

```python
from mcp_server_langgraph.core.feature_flags import feature_flags, feature_gated

# Instead of this pattern:
def execute_task(self, task: str):
    feature_flags.require_feature("enable_multi_agent_orchestration", "Multi-Agent Orchestration")
    # ... implementation

# Use the decorator:
@feature_gated("enable_multi_agent_orchestration", "Multi-Agent Orchestration")
def execute_task(self, task: str):
    # ... implementation

# Works with async functions too:
@feature_gated("enable_programmatic_tools", "Programmatic Tools")
async def call_tool(self, tool_name: str, args: dict) -> ToolResult:
    # ... implementation
```

**Benefits:**
- Cleaner, more declarative syntax
- Automatic handling of sync/async functions
- Consistent error messages
- Respects `FF_TEST_MODE` for testing

##### Test Mode Example

```python
# In tests/conftest.py - enables test mode for all tests
import os
os.environ["FF_TEST_MODE"] = "true"

# Or for specific tests, temporarily disable test mode to verify feature gating:
from mcp_server_langgraph.core.feature_flags import feature_flags
```

##### Multi-Framework Parity Feature Flags

The following feature flags enable capabilities for parity with Claude Agent SDK, Google ADK, and OpenAI Agents SDK (see ADR-0077, ADR-0078, ADR-0079):

<ParamField path="FF_ENABLE_COMPUTER_USE" type="boolean" default="false">
  **Computer Use Tools**

  Enables computer automation tools (mouse, keyboard, browser navigation). When enabled, agents can interact with browser-based UIs via simulated clicks, typing, and navigation.

  **Tools enabled:**
  - `mouse_click`, `mouse_move`, `mouse_drag`
  - `keyboard_type`, `keyboard_press`
  - `scroll`, `navigate`, `go_back`, `go_forward`
  - `fill_form`, `select_option`
  - `get_screen_info`, `get_element_info`

  **Security Note:** Enable only in sandboxed environments. URL validation blocks localhost/internal IPs.
</ParamField>

<ParamField path="FF_ENABLE_LOOP_AGENT" type="boolean" default="false">
  **LoopAgent Orchestration Pattern**

  Enables the LoopAgent pattern from Google ADK for iterative task execution until a termination condition is met.

  **Use Cases:**
  - Iterative refinement workflows
  - Retry-until-success patterns
  - Progressive data processing

  **Example:**
  ```python
  loop_agent = LoopAgent(
      max_iterations=10,
      termination_condition=lambda state: state.get("done", False)
  )
  ```
</ParamField>

<ParamField path="FF_ENABLE_SESSION_FORK" type="boolean" default="false">
  **Session Fork Capability**

  Enables conversation branching for Claude Agent SDK parity. Create multiple alternative conversation paths from a single point.

  **Use Cases:**
  - A/B testing different agent responses
  - Parallel exploration of approaches
  - Safe experimentation without affecting main session

  **API:**
  ```python
  fork_manager = SessionForkManager(checkpointer)
  fork_result = await fork_manager.fork_session(
      session_id="main-session",
      fork_point="checkpoint-123"
  )
  ```
</ParamField>

<ParamField path="FF_ENABLE_LLM_HOOKS" type="boolean" default="true">
  **LLM-Level Callbacks**

  Enables `BEFORE_MODEL` and `AFTER_MODEL` hooks for intercepting LLM requests/responses.

  **Capabilities:**
  - Modify prompts before LLM call
  - Cache LLM responses
  - Filter/redact LLM output
  - Add disclaimers to responses
</ParamField>

<ParamField path="FF_ENABLE_SESSION_HOOKS" type="boolean" default="true">
  **Session Lifecycle Hooks**

  Enables `SESSION_START` and `SESSION_END` hooks for session lifecycle management.
</ParamField>

<ParamField path="FF_ENABLE_HANDOFF_PATTERN" type="boolean" default="true">
  **Agent-to-Agent Handoff**

  Enables explicit agent-to-agent handoffs from OpenAI Agents SDK pattern.
</ParamField>

```python
class FeatureFlags:
    """Environment-based feature flags"""

    def __init__(self, env: str):
        self.env = env

    @property
    def enable_caching(self) -> bool:
        """Enable LLM response caching"""
        return self.env in ["stg", "production"]

    @property
    def enable_rate_limiting(self) -> bool:
        """Enable API rate limiting"""
        return self.env == "production"

    @property
    def enable_tracing(self) -> bool:
        """Enable distributed tracing"""
        return self.env in ["stg", "production"]

    @property
    def enable_load_shedding(self) -> bool:
        """Enable load shedding under high load"""
        return self.env == "production"

    @property
    def verbose_errors(self) -> bool:
        """Show detailed error messages"""
        return self.env == "development"

## Usage
features = FeatureFlags(settings.env)

if features.enable_caching:
    # Use Redis cache
    cache = RedisCache(settings.redis_url)
```

    ```python
    # Fail fast on startup
    @app.on_event("startup")
    ```

### Troubleshooting

<AccordionGroup>
  <Accordion title="Environment variables not loaded">
    **Problem**: Settings show default values instead of .env values

    **Solutions**:
    ```python
    # Check .env file location
    import os
    print(f"Current directory: {os.getcwd()}")

    # Verify .env is being loaded
    from dotenv import load_dotenv
    load_dotenv(verbose=True)

    # Check specific variable
    print(f"ANTHROPIC_API_KEY: {os.getenv('ANTHROPIC_API_KEY', 'NOT SET')}")
    ```
  </Accordion>

  <Accordion title="Configuration validation fails">
    **Problem**: Application exits on startup

    **Solutions**:
    ```bash
    # Check required variables
    python -c "from src.config import settings; print(settings)"

    # Validate .env format
    cat .env | grep -v '^#' | grep -v '^$'

    # Test individually
    export ANTHROPIC_API_KEY=test
    python -c "from src.config import settings"
    ```
  </Accordion>

  <Accordion title="Kubernetes ConfigMap not updating">
    **Problem**: Pods use old configuration

    **Solutions**:
    ```bash
    # Force update
    kubectl rollout restart deployment/mcp-server-langgraph

    # Check ConfigMap
    kubectl get configmap mcp-server-langgraph-config -o yaml

    # Watch pod restart
    kubectl get pods -w
    ```
  </Accordion>
</AccordionGroup>
